Lesson 04 — Setup

Map your account: contracts, groups, and products

The IDs every later cmdlet asks for — where they come from, how they nest, and how to never type them by hand.

~12 min Needs: working .edgerc Read-only — totally safe Build your account map

Where this sits. Lesson 03 got Get-AccountID working. Every cmdlet from Lesson 05 onward — find a property, create a security config version, make a client list — wants a contract ID and/or a group ID. This lesson shows you where they live and how to pull them once into a reusable “account map.”

The win: a small table on your screen showing every group you can work in, its contract, and the products on that contract — and the two or three IDs you'll paste all week held in variables.

1How Akamai IDs nest

Account  (act_1-2ABCDE)
 ├─ Contract  (ctr_1-3CV382)  ── Products: Ion, DSA, AAP, ...
 │   └─ Group  (grp_183542)   ← properties & security configs live here
 │        └─ Group  (grp_183544)   ← groups form a tree
 └─ Contract  (ctr_1-3CV383)  ── Products: ...
  • Contract — your commercial agreement. Determines which products you can use.
  • Group — an access-control folder. Properties, includes, and security configs belong to one group. Groups nest, and a group is tied to one or more contracts.
  • Product — e.g. prd_Fresca (Ion), prd_SPM (AAP). Needed when you create a property.
The prefixes act_ account · ctr_ contract · grp_ group · prd_ product. Some cmdlets accept the bare number (183542), some want the prefix (grp_183542). When in doubt, include the prefix — it always works.

2Pull the IDs

Account

$acct = Get-AccountID
$acct
act_1-2ABCDE

Contracts

Get-PropertyContract
ctr_1-3CV382
ctr_1-3CV383

# richer detail (contract type, status):
Get-Contract | Select-Object contractId, contractTypeName

Groups — the tree

$groups = Get-Group
$groups | Select-Object groupName, groupId, parentGroupId, contractIds

groupName            groupId     parentGroupId  contractIds
---------            -------     -------------  -----------
Example-Account - Top       grp_183542                 {ctr_1-3CV382}
Example-Account - Web       grp_183544  grp_183542     {ctr_1-3CV382}
Example-Account - Security  grp_183551  grp_183542     {ctr_1-3CV382}

Find one by name instead of scrolling:

Get-Group -GroupName "*Security*"

Products on a contract

Get-Product -ContractID ctr_1-3CV382 | Select-Object productId, productName
productId   productName
---------   -----------
prd_Fresca  Ion
prd_SPM     App & API Protector

3You can often pass a name, not an ID

The module keeps an in-memory data cache that resolves names → IDs for you. So many cmdlets accept -GroupName "Example-Account - Web" and look up grp_183544 themselves. That is convenient, but:

  • Names are not unique across the tree; IDs are. For anything you write, use the ID.
  • If a lookup seems stale after you create a group/property, refresh it: Clear-AkamaiDataCache then New-AkamaiDataCache.

4Turn on the safety options (once)

These make every later lesson more forgiving. Run once per session (or add to $PROFILE):

Set-AkamaiOptions -EnableErrorRetries $true `
                  -EnableRateLimitRetries $true `
                  -EnableRateLimitWarnings $true
Get-AkamaiOptions   # confirm

Retries handle transient 5xx/429 responses; the warning tells you when you're near an endpoint's rate limit before it bites.

5The escape hatch

No cmdlet for something? Every Akamai REST endpoint is reachable directly, still EdgeGrid-signed:

Invoke-AkamaiRestMethod -Method GET `
    -Path "/papi/v1/contracts"
Invoke-AkamaiRestMethod -Method GET -Path "/papi/v1/groups" -Section example-account

Useful for reading a brand-new API before the module wraps it — and for learning what a cmdlet does under the hood (Get-Help <cmdlet> -Full often names the endpoint).

Try it — build your account map

Run this. It joins groups to their products so you can see, in one table, where you can work and what's available there.

$contracts = Get-PropertyContract
$groups    = Get-Group

foreach ($c in $contracts) {
    $products = (Get-Product -ContractID $c).productName -join ', '
    $groups |
      Where-Object { $_.contractIds -contains $c } |
      Select-Object @{n='Group';e={$_.groupName}},
                    @{n='GroupId';e={$_.groupId}},
                    @{n='Contract';e={$c}},
                    @{n='Products';e={$products}}
} | Format-Table -AutoSize

Then pick the group you'll use for the property lessons and stash its ID:

$grp = 'grp_XXXXXX'   ;   $ctr = 'ctr_X-XXXXXX'
Show expected shape & notes
  • A table: one row per (group × contract), with a comma-joined product list. Groups tied to two contracts appear twice — expected.
  • @{n='Name';e={...}} is a calculated property — it builds a custom column with Select-Object. You'll reuse this pattern constantly.
  • Empty Products for a contract usually means your API client lacks the Products API grant — harmless for the rest of the course.
  • Save it for later: append | Export-Csv $HOME\akamai-account-map.csv -NoTypeInformation.
