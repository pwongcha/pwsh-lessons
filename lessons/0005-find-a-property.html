Lesson 05 — Property Manager

Find a property and read its state

Search by name or hostname, then pull version status, hostnames, activation history, and the rule tree — everything the Property Manager screens show you, from the shell.

~15 min Read-only — safe Needs: working .edgerc First real task

Where this sits. Setup is done. This is the first task from your mission. Everything here is a Get- or Find- — you cannot break anything. The goal is to get fast at answering “what version is live, on what hostnames, changed by whom, doing what” without opening Control Center.

The win: one screen of output that profiles any property — its live/staging versions, its hostnames, its last few activations, and its top-level rules.

1Find the property

Find-Property searches. It has four modes — pick by what you know:

Find-Property -PropertyName '*www*'          # by property name (wildcards ok)
Find-Property -PropertyHostname www.example.com  # by a hostname it serves
Find-Property -EdgeHostname www.example.com.edgekey.net
Find-Property -IncludeName '*origin*'          # by include name

Narrow to what is active:

Find-Property -PropertyName '*shop*' -JustProductionActive
Find-Property -PropertyName '*shop*' -Latest

The result gives you the property name, its propertyId, the matching version, and the group/contract — the identifiers the next cmdlets want.

2Open the property record

$p = Get-Property -PropertyName www.example.com

$p | Select-Object propertyName, propertyId, latestVersion,
                       stagingVersion, productionVersion, groupId, contractId

propertyName      : www.example.com
propertyId        : prp_678901
latestVersion     : 14
stagingVersion    : 14
productionVersion : 12
groupId           : grp_183544
contractId        : ctr_1-3CV382

Already this tells you: v12 is live, v14 is on staging, and there are unreleased edits in v13–v14.

If Get-Property errors with “multiple properties” The name exists in more than one group. Add the ones from your account map: Get-Property -PropertyName x -GroupID grp_183544 -ContractId ctr_1-3CV382.

    Sort-Object propertyVersion -Descending |

Get-PropertyVersion -PropertyName www.example.com -PropertyVersion latest

4Which hostnames does it serve?

Get-PropertyHostname -PropertyName www.example.com -PropertyVersion latest |
    Select-Object cnameFrom, cnameTo, certStatus

cnameFrom            cnameTo                              certStatus
---------            -------                              ----------
www.example.com      www.example.com.edgekey.net          {@{status=DEPLOYED...}}
img.example.com      img.example.com.edgekey.net          {@{status=DEPLOYED...}}

cnameFrom is the customer-facing hostname; cnameTo is the edge hostname the DNS CNAME must point at.

5Activation history

Get-PropertyActivation -PropertyName www.example.com |
    Sort-Object submitDate -Descending |
    Select-Object propertyVersion, network, status, submitDate, note -First 6

propertyVersion network  status   submitDate            note
--------------- -------  ------   ----------            ----
             14 STAGING  ACTIVE   2026-08-28T09:14:00Z  cache tuning
             12 PRODUCTION ACTIVE 2026-08-19T12:20:11Z  Q3 origin move
             12 STAGING  ACTIVE   2026-08-19T11:40:03Z  Q3 origin move

This is the audit trail: who pushed which version to which network, and when.

6Read the rule tree

Get-PropertyRules returns the whole configuration as one big object. Don't print it raw — navigate it.

$r = Get-PropertyRules -PropertyName www.example.com -PropertyVersion latest

$r.rules.name                # "default"
$r.rules.children.name       # the named child rules
Offload
Performance
Origin Failover
mPulse RUM

# the default-rule behaviors (origin, caching, cpCode...):
$r.rules.behaviors.name
origin
cpCode
caching
allowPost

# inspect one behavior's settings:
($r.rules.behaviors | Where-Object name -eq 'origin').options |
    Select-Object originType, hostname, forwardHostHeader
originType              hostname                 forwardHostHeader
----------              --------                 -----------------
CUSTOMER                origin-www.example.com    REQUEST_HOST

Working on it offline or diffing it? Write it to a file:

Get-PropertyRules -PropertyName www.example.com -PropertyVersion latest `
    -OutputToFile -OutputFileName www-v14.json
The shape to remember A rule tree is one root rules object. Every rule has behaviors[], criteria[], and children[] (nested rules). That recursion is the entire model — Lesson 06 edits it, Lesson 08's security custom rules echo it.

Try it — profile a real property

Pick any property on your account. Fill in its name and run this block. It produces a one-screen profile.

$name = 'YOUR-PROPERTY-NAME'

$p = Get-Property -PropertyName $name
"`n=== $($p.propertyName)  ($($p.propertyId)) ==="
"live v$($p.productionVersion) | staging v$($p.stagingVersion) | latest v$($p.latestVersion)"

"`n-- hostnames --"
Get-PropertyHostname -PropertyName $name -PropertyVersion latest |
    Select-Object cnameFrom, cnameTo | Format-Table -AutoSize

"`n-- last 3 activations --"
Get-PropertyActivation -PropertyName $name |
    Sort-Object submitDate -Descending |
    Select-Object propertyVersion, network, status, note -First 3 | Format-Table -AutoSize

"`n-- top-level rules --"
$r = Get-PropertyRules -PropertyName $name -PropertyVersion latest
$r.rules.children.name

"`n-- origin --"
($r.rules.behaviors | Where-Object name -eq 'origin').options.hostname
Show what to expect & how to read it
  • live vs latest gap — if productionVersion < latestVersion, someone has staged or draft changes not yet in production.
  • origin under a child rule? — $r.rules.behaviors only shows the default rule. If origin is empty there, it's set in a child: $r.rules.children | Where-Object { $_.behaviors.name -contains 'origin' }.
  • no activations — brand-new property never pushed anywhere.
  • Backtick-n (`n) inside a double-quoted string is a newline — that's how the block gets its spacing.
